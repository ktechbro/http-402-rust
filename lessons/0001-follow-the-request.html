RUST · UBUNTU · TUTORIAL 1

Follow one request

Your goal: run the example and explain why the same endpoint first returns 402 and then 200. This project uses an invented payment scheme and a public token. No funds move.

Client GET → API 402 + challenge → client builds demo payload → client retries → API checks payload → 200 + protected data

1. Start the Ubuntu API

In a terminal, change to the repository directory and run:

docker compose up --build -d --wait api
docker compose exec api curl -i http://127.0.0.1:3000/health
docker compose exec api curl -i http://127.0.0.1:3000/premium

The curl commands run inside the API container. Look for 200 on the public health route and 402 on the premium route. The challenge is encoded in the response header and mirrored as readable JSON in the body.

2. Follow the Rust handler

Open src/lib.rs. app() maps GET /premium to premium(). That handler reads payment-signature. With no header, it builds a challenge using resource() and requirements(), encodes it with Base64, and returns 402.

If the header exists, the handler decodes Base64, parses JSON into DemoPayment, and checks version, resource, selected terms, and the token. Every check must pass before returning the protected data.

3. Let the client retry

docker compose run --build --rm demo

The Bash script in scripts/demo.sh makes the unpaid request, reads the challenge header, and uses jq to copy its resource and first payment option into a retry payload. It adds the demo token, encodes the payload, and retries. Observe the final 200.

4. Predict, then test

What happens if the retry header is not valid Base64?

docker compose exec api curl -i -H "PAYMENT-SIGNATURE: invalid" http://127.0.0.1:3000/premium
Reveal expected result

402 again. The decoding chain produces no valid DemoPayment, so the server returns a fresh challenge without protected data.

Why would knowing the demo token let anyone unlock the resource?

Reveal explanation

The check compares public strings and JSON values. There is no private signing key or blockchain verification. Base64 adds no authenticity.

5. Check and stop

docker compose run --build --rm checks
docker compose down

The checks container runs formatting, four lifecycle tests, and Clippy. The API runs continuously; demo and checks are temporary containers.
